# 交互流程

## 记录与排名

搜索/详情 → 记录用餐（已去过显示“再去了一次”） → 三种感受 → 可选笔记、标签、菜品、分店、日期、照片 → 仅保存记录，或进入比较 → 完成。

比较只在同感受的已排名餐厅中二分插入。点击左/右餐厅或左右滑动选择；Undo 回退尚未提交的比较；Skip for now 退出且不保存当前草稿。完成后写入独立 VisitEntry 与唯一餐厅名次；重新排名入口只改名次，不增加到访。结果页与榜单可以撤销最近一次提交。

没有同感受的旧餐厅时直接建立该感受分组的第一个名次，不编造比较对象。分数由有序分组派生；没有排名时不显示数字。详细算法另见 RANKING-MODEL。

## 多次用餐

新增到访不会覆盖前一次笔记、菜品、照片或日期。日期可不填，不把“记录创建时间”当成实际到访日期；原数据中的月精度仍只显示年月。分店由用户选择/填写，不从同品牌推断每个分店均去过。原资料只有餐厅级记录，不能自动生成历史次数。

## 列表 / 地图 / 搜索

地区、菜系、价格、照片条件取交集；未知价格被价格条件排除。缺坐标的餐厅继续在列表/搜索中出现，地图显示缺位置数量。地图点位仅选中预览，点击预览才进入详情。返回保留 App 层的筛选状态；路由滚动恢复仍待精修。

## 照片

Feed 和详情的同一组实拍支持原生横向滑动、圆点/页码、桌面箭头。点击打开原比例全屏；键盘左右键切图，Esc 关闭，恢复此前焦点。单图不出现多图控件。新增照片使用 IndexedDB 保存，云端配置后按用户路径上传私有 Storage。

## 共享

打开任意路由 → 恢复已保存会话 → 无会话时只显示独立登录页 → 选择 WXY / LHJ 并输入密码 → 云端验证 → 载入本人记录 → 首页。有效会话下重新打开或刷新可直接恢复目标页面；载入期间只显示状态页，不渲染个人 Feed、导航或上一账号内容。密码错误留在登录页；读取失败显示重试；Profile 退出后回到登录页。

现有两账号已经在同一空间，无须重新创建或加入。新项目首次配置时，登录后可创建空间/通过邀请码加入，最多二人。第二位成员从空白个人记录开始，不复制 WXY 的已去过与排名。两人的记录分别保存，共同想去清单共享。版本号检查拒绝覆盖另一台设备的新状态，冲突时提供载入云端与重试。两账号真实云端联调已通过。
