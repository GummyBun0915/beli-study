# 总规格 / 当前状态

更新：2026-10-23。新目录独立开发；上游只读。产品以真实餐厅数据支撑可运行体验，优先复刻已核实的 Beli 信息架构、交互序列和视觉层次。

## 证据与架构决策

1. 基线使用 2026-10-22 可取得的 Apple 商店素材；具体 build 未核实。2026-09 Pratt 的真实操作图只补充明确出现的流程。2023/2024 材料标为历史，不混作当前像素证据。
2. 前端采用 React + TypeScript + Vite。原 Astro 站是静态内容发布；新应用需要连续的记录向导、用户状态与共享会话，因此在新目录建立应用状态，未改动上游栈。
3. 浏览器默认离线保存个人状态；二人异地共享使用可选 Supabase Auth / Postgres RLS / Storage / Realtime。未配置时无网络同步，也不虚构好友数据。
4. 数字分数由三种感受及比较产生的有序列表派生；算法公开写在 RANKING-MODEL，不声称等同于 Beli。
5. Restaurant 与 Visit 分离。每家餐厅只占一个名次；重复到访增加独立记录，重新排名不生成新到访。
6. 数据来源与研究说明只放工程文档。界面不显示上游品牌、评级体系或“真实导入”宣传文案。

7. 二人身份固定为 WXY / LHJ，前端选择身份、输入密码；内部账号地址仅用于 Auth，不要求收邮件。密码由云端验证，绝不存入源码或文档。两个账号可使用用户指定的同一初始密码。所有路由先经过独立登录页；有效会话自动恢复，确认身份并载入本人记录后才显示应用。Feed 使用当前用户姓名说明记录归属。

## 已实现

Feed、餐厅搜索、Been/Want to Try、城市/菜系/价格筛选、地图/列表、定位选点预览、详情、多图轮播与灯箱、三种感受、可选笔记/标签/菜品/日期/分店/照片、比较插入排名、撤销、重复用餐时间线、WXY 蓝底 W 资料页。Recs 是本地按用户喜欢菜系筛选的近似推荐；Guides 是已有餐厅的地区探索，不伪造预订时段。
