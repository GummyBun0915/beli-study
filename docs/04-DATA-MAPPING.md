## Import boundary and integrity

This app imports the exact bytes of `src/data/restaurants.generated.json`, the public projection already consumed by `dachitech`, plus each image named by that projection. The private workbook, raw Notion data, photo matching workspace and overrides are not copied. The source project is read-only to this app. `scripts/sync-source.mjs` checks IDs, coordinate pairs, image references and file hashes before it writes the imported copy. `data/source-manifest.json` records SHA-256 hashes for the projection and every imported image. Use `--check` to verify the imported snapshot against the current source.

## Field mapping

| `dachitech` public field | New app field/use | Rule |
|---|---|---|
| `id`, `slug` | stable identity | Keep unchanged; local user actions key by `id`. |
| `brand`, `branch` | `displayName` | Join with ` · ` only when a branch is present; original strings stay intact. |
| `regionSlug`, `actualCity` | region and location labels | Preserve; the region may be a country, so `actualCity` is not silently recast as a city. |
| `recommendationLevel` | `status`, guide label | Only `daiChi` maps to `want`; every other source level maps to `been`, matching the source's `isEaten` helper. Source levels remain visible as their own labels. They are **not** Beli ratings. |
| `score10`, `scoreScope` | source rating | Preserve nullable values. All 75 current `score10` values are `null`; no score is synthesized. |
| `visitedAt`, `visitedAtPrecision`, `inRecent` | diary date/feed | Preserve day vs month precision. Month values display `YYYY.MM` with no invented day. `inRecent` comes from the source. |
| `reviewText`, `dishes` | detail text, feed copy | Use only supplied text and dish names; missing reviews remain missing. |
| `cuisineTags`, `category` | search/filter | Search real tags; `category` is `null` for all current records, so no category classification is fabricated. |
| `avgPrice`, `address` | detail/search/filter | Preserve nullable price and empty addresses. |
| `lng`, `lat`, `coordSystem` | `mapLng`, `mapLat` | 30 GCJ-02 source pairs are transformed once to WGS84 for the WGS84 Leaflet basemap; six WGS84 pairs pass through. The 39 missing pairs remain `null` and never acquire a guessed map marker. Raw coordinates and the original system remain on each record. |
| `coverImage`, `images` | `coverUrl`, photo gallery | Prefix the public asset path with the app base URL. Preserve all source image order, dimensions and crop positions. Empty photo sets use a text empty state. |
| `amapQuery`, `regionSlug` | `navigationUrl` | Match the source navigation rule: Chinese regions → 高德; Japan, Singapore and Thailand → Google 地图. Keep the source's already encoded query. |
| `branches` | related branches | Preserve as source suggestions; branch records have no explicit coordinate system, so their points are not plotted by this adapter. |
| `closed` | closure status | Preserve and label; closed records must not be shown as open recommendations. |

`src/data/restaurants.ts` retains every public source field in each `Restaurant` and adds only derived display, search, navigation and map fields. The source JSON is never edited at runtime.

## Gaps for Beli features

- The public projection contains **no** account, friend, follow, feed activity, comments or social graph. A diary feed can use real imported visits; it cannot claim friends visited a restaurant.
- No Beli rating or comparison history exists. The app may store **new** user scores and pairwise outcomes locally, but must not present source guide levels as a 0–10 Beli score.
- Only 36 of 75 restaurants can have truthful map pins. The other 39 remain in list and search results with a missing-location state.
- 41 restaurants have no source cover; 52 have no address; 66 have no price. The UI must show omissions plainly.
- `category` has no values. Filters can use existing region, cuisine tags, status, guide level and price where available.
- The snapshot is public data as of 2026-10-21. New source edits require a deliberate resync and review.
