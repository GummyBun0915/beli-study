# 比较驱动的本地排名模型

上游 75 家餐厅没有整店数字评分。任何源推荐等级都不参与新分数，也不出现在产品界面。

用户选择 liked / fine / disliked 三种感受之一。新餐厅在同感受的已排名列表中，通过二分比较确定插入位置。不同感受分组保持 liked → fine → disliked 的顺序。一家餐厅只有一个 ID 和一个当前名次；重新排名先移出自身，再重新插入。

分数是透明的近似派生：liked 区间 6.7–10，fine 区间 3.4–6.6，disliked 区间 0–3.3。分组有 n 家时，第 i 名（从 0 开始）的分数为 `low + (high-low) × (n-i)/(n+1)`，四舍五入为一位小数。分组扩展时旧分数会相应变化，但相对次序保持。此区间与公式属于本项目实现选择，不是已验证的 Beli 算法。

记录与排名分离：VisitEntry 保存每次真实用餐的日期、分店、菜品、笔记、标签和照片；可以仅保存新到访而不动排名。没有同感受的已排名餐厅可比较时，普通记录流程只保存 VisitEntry，不把该餐厅自动放在榜首，也不生成分数；用户从详情明确加入榜单后，才建立第一个名次。排名向导完成比较时才提交新名次，取消或跳过不保存草稿。状态和最近 20 次提交快照保存在版本 2 localStorage，可撤销；图片文件独立保存在 IndexedDB。旧原型中用户手动输入的数字只用于迁移到感受和顺序，原型滑杆已移除。

初始 WXY 状态可沿用公开数据的 been/want；共享空间第二成员使用 empty baseline，未记录为 none。禁止将 WXY 的历史当作对方到访。

2026-11-06 用户新要求优先：允许编辑历史十分制评分；历史导入/手填值优先展示，不用近似比较公式重算。没有显式分数的新记录仍可走比较流程。导入的 source 评分仅 WXY 可获得，LHJ 不继承。
